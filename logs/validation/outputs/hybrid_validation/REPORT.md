# 창원국가산단 단계형 Hybrid 후보 구조 감사·검증

CW-HYB-1.0 / 2026-09-18

공식 검증명: **재구축 패널 기반 사후적 시간외 정합성 검증(retrospective reconstructed-panel temporal validation)**의 고정 출력 기반 workflow 후보 평가.

# 1. 결론

**역할분리는 실제 판정에서 성립한다. 다만 Primary Hybrid를 즉시 최종모형으로 교체할 근거는 충분하지 않다.** Primary를 시범운영 검토용 확장 후보로 보존하고, 현 최종 triage_final과 기존 산출물은 유지하는 판단을 권고한다. 사용자 제시 결론 중 **E(향후 확장안)와 D(현재 최종모형 유지)**에 가깝다. 이는 triage_final의 미래 위축 포착 성능이 더 좋아서가 아니라, Hybrid의 추가 업무부담·상충신호 처리·현장 수용성이 검증되지 않았기 때문이다.

후보 중에는 강한 **최종 Triage 단계2**를 gate 밖에서도 보존하는 Primary의 논리가 Strict Serial보다 안전하다. 하지만 이번 자료에서 그 override 사례는 0행이므로 Primary와 Strict를 실증적으로 판별할 수 없다. Strict가 강신호를 실제로 제거했다고 주장하지 않는다.

핵심 발견은 다음과 같다.

- 주140행에서 두 Hybrid는 CHECK+가 ELECTRE와 **완전히 동일**, PRIORITY가 Triage와 **완전히 동일**했다. 새 정보나 포착 우위가 생긴 것은 아니다.
- ELECTRE CHECK+·Triage 관찰 26행 중 양성10행이 추가확인 후보로 들어온다. 반대로 ELECTRE 관찰·Triage 추가확인 **2행은 모두 양성이며 두 Hybrid에서 관찰로 내려간다.** 이 부작용을 숨기지 않았다.
- 두 Hybrid가 동일한 것은 해당 자료에 E=0,T=2 사례가 없기 때문이다. **Priority=Triage priority라는 Primary의 성질은 규칙상 필연**이지 검증에서 새로 발견된 장점이 아니다.
- 결측 fallback은 업무흐름을 이어 주지만, 생산 미확인20행의 양성9행을 하나도 선별하지 못했다. 운영 포괄성의 확대와 outcome 포착 개선은 다르다.
- 공통표본에서 Hybrid는 67행을 확인후보로 두고 그중12행을 우선점검으로 둔다. Triage 단독보다 확인후보가 순24행 늘지만 실제 인력·시간·비용·현장 타당성 자료가 없다.

# 2. Hybrid 구조

모형 내부의 가중치·lambda·profile·q/p·E/R/A/P·300인 gate·반복·생산 보강은 변경하지 않았다. 기존 rolling의 `electre_fixed`, `triage_final` 출력만 사용했다. 새 Hybrid는 정확히 두 개다.

E∈{-1,0,1,2}, T∈{0,1,2}; -1=ELECTRE 자료보류. H=Primary, S=Strict Serial.

| ELECTRE E | Triage T=0 | Triage T=1 | Triage T=2 |
| --- | --- | --- | --- |
| -1 자료보류 | H=0 / S=0 (fallback) | H=1 / S=1 (fallback) | H=2 / S=2 (fallback) |
| 0 관찰 | H=0 / S=0 | H=0 / S=0 | **H=2 / S=0** |
| 1 CHECK | H=1 / S=1 | H=1 / S=1 | H=2 / S=2 |
| 2 PRIORITY | H=1 / S=1 | H=1 / S=1 | H=2 / S=2 |

```text
Primary:
    if E == -1: H = T
    elif T == 2: H = 2
    elif E >= 1: H = 1
    else: H = 0

Strict Serial:
    if E == -1: S = T
    elif E == 0: S = 0
    elif T == 2: S = 2
    else: S = 1
```

완전자료에서 CHECK+ 집합은 H_CHECK=(E>=1) OR (T=2), S_CHECK=(E>=1)다. H_PRIORITY=(T=2), S_PRIORITY=(E>=1 AND T=2)다. E=-1에서는 둘 다 T를 따른다. **Primary를 구현하면서 E 관찰 업종의 Triage 계산을 생략하면 override가 작동하지 않는다.** “완전 직렬”이라는 표현은 Strict에만 맞는다.

행동 의미:

| 최종 단계 | 제안 행동 | 뜻하지 않는 것 |
| --- | --- | --- |
| OBSERVE 관찰 | 정기 모니터링, 다음 분기 재점검. 원래 Triage 신호·모형 간 불일치도 카드에 표시 | 안전·위기 부재 확정 |
| ADDITIONAL_CHECK 추가확인 | 담당자 자료확인 후보 등록, 기업·현장 확인 필요성 검토 | 지원 선정·필수 현장방문 자동 지시 |
| PRIORITY 우선점검 | 담당자 검토·현장확인의 우선순위 부여 | 위기 확정·예산 배정·사업 처방 |

Triage 핵심자료보류는 현재180행에 없었다. 향후 T=-1이 발견되면 이번 코드가 새 결합정책을 추정하지 않고 중단한다. 해당 결측 정책은 별도 승인이 필요하다.

# 5. CHECK 이상 결과

**ELECTRE의 넓은 후보군은 유지됐다. 성능이 ELECTRE보다 좋아진 것은 아니다.** Hybrid CHECK+ 67행/140행(47.86%)과 포착24행은 ELECTRE와 같다. Triage43행 대비 확인후보가 순24행 증가하고 TP는 순8행, FP는 순16행 증가했다.

행별로는 Triage 관찰26행(양성10)을 새 후보로 포함하면서 Triage 추가확인2행(양성2)을 제외했다. 순 차이만 읽으면 이 제외를 놓치게 된다. 비교 모델의 선별집합은 완전 포함관계가 아니다.

Hybrid 후보의 precision35.82%는 주표본 양성률41.43%보다 낮고 BA=.4447<.5다. “더 많이 포착했다”는 기술통계와 “선별이 미래 위축을 잘 구분한다”는 주장은 다르다. 이 모형은 미래 추가 위축을 확정하는 분류기가 아니라 현재 확인후보를 정하는 행정지원 도구다. proxy상 FP가 실제 불필요한 확인이라는 뜻도 아니다.

# 6. PRIORITY 결과

**Triage의 보수적 우선점검 집합은 유지됐다. 이 동일성은 Primary 규칙이 보장한다.** 12행(8.57%) 중 TP6·FP6, recall10.34%, precision50%, FPR7.32%다. ELECTRE의 우선점검33행(23.57%)보다 좁지만 전체 양성58행 중52행을 우선점검으로는 선별하지 않는다.

ELECTRE priority33행 중 Triage0/1인22행은 Hybrid 추가확인으로 내려가고, ELECTRE CHECK인 기계/2022Q1 한 행은 Triage2로 우선점검이 된다. 우선점검에서 내려간22행 중 양성은6행이다. 이22행은 CHECK+ 후보군에 남아 있으므로 전체 workflow에서 삭제된 것은 아니다. 제한된 인력의 집중단계를 설명하는 구조이지 동일 용량에서 최적 효율을 증명한 구조가 아니다. Priority precision50%의 기반도 단12행이다.

# 10. Hybrid의 장점

- 1차 후보와 2차 우선순위를 분리해 두 원모형의 서로 다른 행동 특성을 설명할 수 있다.
- ELECTRE 단계2를 자동으로 자원집중 판정으로 받아들이지 않고 명시적 신호·규모·보강조건을 사용한다.
- Primary는 ELECTRE gate와 무관하게 Triage 최종priority를 보존하는 논리적 안전장치가 있다. 현재표본에는 gate밖 사례가 없다는 한계를 함께 둔다.
- 자료보류를 전체업무 중단으로 바꾸지 않고 Triage의 기존 부분결측 정책·플래그를 유지한다.
- 카드에 두 원모형의 단계·결합이유·상충신호·알 수 없는 원인·확인질문·담당기능을 함께 남길 수 있다. 담당자의 수정/보류는 사람이 기록해야 한다.

이 장점은 **workflow의 분명함과 추적성**에 관한 판단이다. 현장 타당성·효율·성과가 개선됐다는 정량 근거는 아니다.

# 11. Hybrid의 한계

두 모형은 동일 생산·고용 계열을 공유한다. ELECTRE의 고용 하회런, Triage 반복, 상태런은 서로 다른 정의이지만 독립 정보원이 아니다. Q1 상태가 ELECTRE 점수로 직접 들어가거나 Q2를 전체 합성점수로 쓰는 것도 아니다. Q1은 질문/담당기능, Q2는 g1·A·규모·표시순서 등 서로 다른 역할로 전달해야 한다.

관찰·추가확인·우선점검은 행동단계이지 검증된 악화 확률 서열이 아니다. 주표본의 Primary stage별 사건율은 다음처럼 단조 증가하지 않았다.

| Primary 단계 | N | 양성 | 양성률 |
| --- | --- | --- | --- |
| 관찰0 | 73 | 34 | 46.58% |
| 추가확인1 | 55 | 18 | 32.73% |
| 우선점검2 | 12 | 6 | 50.00% |

따라서 “단계가 올라갈수록 미래 위축 확률이 높다”는 설명은 실제 판정과 모순된다. 추가확인은 현재 확인 신호의 조합이지 calibrated risk class가 아니다.

T=1,E=0의 두 양성 신호를 제거하는 문제가 있으며 기타147인의 강한 비율신호도 stage2가 아니라는 이유로 보존되지 않는다. 결과를 본 뒤 이를 구제하는 union·새 후보·새threshold는 만들지 않았다. 원래 Triage 신호는 후보 카드/감사 기록에서 지우지 않지만 이것이 자동 최종판정 변경을 뜻하지 않는다.

더 넓은 후보67행과 좁은 priority12행을 병행하려면 나머지55행을 어떻게 처리할지 운영정의가 필요하다. 현장 인력·확인소요·반복후보의 중복처리·기관 인수 기준이 없어 복잡성 증가보다 행정가치가 큰지 판단할 수 없다. 사람의 검토·현장확인·실제지원 결과는 모두 `NOT_PERFORMED`이며 수행한 것으로 꾸미지 않았다.

이 설계는 이전 성능결과를 보고 제안된 후속 분석이다. 새로운 비인지 표본의 검증이 아니다. 현재 재구축된 보정패널을 사용해 당시 공표시각/vintage·실제 lead time을 복원하지 못했다. 같은 원계열 proxy, 분기공통충격, 업종반복, 중첩horizon, 알려진 오류정정, 2026년 개발규칙의 사후지식은 남는다. 독립표본 검정·CI·bootstrap·F1·AUC·accuracy·모형최적선택을 추가하지 않았다. 6003 theta는 기존 ELECTRE 선호불확실성 검증으로만 남겼으며 Hybrid 조합에 사용하지 않았다.

정의불가도 공개했다. `performance`224행 중 ELECTRE 결측2행은 모든 confusion/rate가NA다. precision NA는38행(그2행 포함)이며 나머지는 선별0건의 업종/분기/규모층이다. recall·FPR·BA NA는 각2행이다. operational_coverage8행의 성능칸NA는 비적용이지 보류를 비악화로 대체한 값이 아니다. 교차표에서 N0 셀의 양성률은NA다. 상세 NA와 희소경고는 hybrid_metrics/hybrid_overlap에 모두 보존했다.

# 13. 공모전에서 사용하면 안 되는 주장

- “두 모형의 장점을 결합해 성능이 개선됐고 기존모형보다 우수하다.” 동일성은 결합규칙·현재 overlap의 결과다.
- “독립 외부검증·실시간 백테스트·위기예측 정확도 검증을 통과했다.” 당시 가용정보·외부정답이 없다.
- “높은 단계일수록 미래 위축 확률이 높다” 또는 “CAI가 위축 확률이다.” 해당 주장은 현재 사건율 및 불확실성 의미와 맞지 않는다.
- “Strict가 실제 강신호를 제거했다”, “Primary override의 효과를 실증했다.” 관련 실제사례가0행이다.
- “Fallback으로 양성 포착이 개선됐다.” 20행에서 포착양성0이다.
- “모든 Triage 신호를 보존했다”, “소규모 강신호도 모두 override로 보호한다.” Triage1 두행이 제거됐고 <300 priority는0이다.
- “FP는 낭비, FN은 정책실패”, “지원성과·실업예방·행정비용절감을 증명했다.” 현장/개입/비용 자료가 없다.
- “외부 기업사건이 업종 전체 정답이다.” usable True 라벨은0건이다.
- “공식 위기지정, 기업선정, 지원사업·예산배분을 자동 결정하는 새 시스템.” 요청한 의사결정지원 범위를 벗어난다.

# 14. 최종 의사결정 흐름

후보 workflow의 정상 흐름:

Q1 상태 / Q2 규모 / Q3 시간의 cutoff내 사실
→ ELECTRE fixed crisp screening
→ 명시적 Triage escalation
→ 업종 진단카드
→ 담당자 검토
→ 기업·현장 확인
→ 기존 기업지원·고용지원·직업훈련 체계 검토
→ 다음 분기 재점검.

예외·역할을 함께 설명해야 한다.

- 모든 업종에서 Triage 최종priority를 병행 확인한다. E 관찰이어도 T2이면 Primary 우선점검이다. 이 경로 때문에 Primary는 완전직렬이 아니다.
- E 보류는 Triage fallback으로 흐름을 이어가되 생산 미확인·최소판정 표시를 유지한다.
- Q1은 원인/순위를 확정하지 않고 질문·담당기능을 정한다. Q2는 영향·규모·같은단계 처리순서를 설명한다. Q3의 ELECTRE 고용하회런, Triage 진입반복, 카드상태런은 분리 표시한다. 미래전환/전체런은 입력이 아니다.
- 카드는 E/T/H 세 단계를 구분하고 특히 원래T1이H0이 된 경우를 표시한다. 사후 outcome 열은 감사용 부속필드로 분리하며 실제 담당자 카드에 당시 입력처럼 표시하지 않는다.
- 담당자는 검토자·현장근거·지원검토결과를 기록하고 수정·보류 판단을 한다. 모형은 해당 지원체계의 사업·기업·예산을 자동 선택하지 않는다. 이번 분석에서 사람의 검토·현장확인은 실제로 수행하지 않았다.

## 실행·산출물 검산 기록

규칙/사양은 신규Hybrid 성능 전에 CW-HYB-1.0 PROTOCOL과 EXECUTION_LOCK으로 잠갔다. overlap을 먼저 저장하고 Hybrid 판정파일을 별도해시로 잠근 뒤 지표를 계산했다. CW-RBT-1.0 PROTOCOL/FREEZE와 기존 rolling 출력hash를 확인했고 평가행·A/B단계·A/B지표가 일치했다. 결합함수 입력은 기존E/T stage 두 개뿐이다. 기존 6003 parameter 결과는 재조합하지 않았다.

검증코드 `scripts/run_hybrid_validation.py`, 신규단위테스트 `tests/test_hybrid_validation.py`. --prepare(기존결과확인·overlap·판정잠금), --evaluate(지표·사례). 기존lock/결과가 있으면 덮어쓰기 거부. 원최종/rolling/ELECTRE/외부사건 산출물과 README·노트북을 보호해 해시 대조했다. 신규Hybrid 후보폴더만 작성했다. 프로토콜 이탈 없음.

최종 QA는 신규Hybrid12개 및 기존시간외검증10개, 합계22개 테스트를 통과했다(실패/skip0). 12조합 전체 truth table, 모든180행 결합판정의 독립 대수검산, 모든224 performance행의 confusion/rate, 기존140행 mask·원단계·사후라벨 재사용, 전체67양성 기준 capture, 보류를FN으로 바꾸지 않음, 카드의 과거고용증감·담당자검토 미실시 표시를 확인했다. 기존시간외검증의810 outcome·6003 theta 검산도 그대로 통과했다.
