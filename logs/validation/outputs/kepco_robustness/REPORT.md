## 1. 무엇이 바뀌었나

직전까지 KEPCO 는 "endpoint 를 알 수 없다"는 이유로 `PARTIAL` 에 멈춰 있었다.
이번에 **로그인한 브라우저로 포털 `OPEN API 소개` 화면을 직접 열어**
(데이터공개 > OPEN API > OPEN API 소개, `cmsmain.do?scode=S01&pcode=000493`)
공식 요청 URL·인자·응답 필드를 확보하고 실제로 호출했다. 로그인 우회는 하지 않았다.

이전 기록의 오판 하나를 바로잡는다. `powerUsage/industryType.do` 가 돌려준
`errCd=404` 를 "업무명이 틀렸다"로 읽었지만, 포털 상태코드표는 **404 = 요청자료를
찾을 수 없음**이다. 경로는 처음부터 맞았고 인자가 문제였다.

그런데 명세를 확보한 뒤에도 상태는 `PARTIAL` 로 남는다. 이유가 바뀌었을 뿐이다.
**이전: 명세를 몰라서. 지금: 1순위 자료의 원자료가 2021년 내내 비어 있어서.**

## 2. 확보한 공식 명세

| API | endpoint (`https://bigdata.kepco.co.kr/openapi/v1/…`) | 필수 인자 | 선택 인자 |
|---|---|---|---|
| 업종별 전력사용량 | `powerUsage/businessType.do` | `year`,`month`,`apiKey` | `metro`,`city`,`bizType`,`returnType` |
| 산업분류별 전력사용량 | `powerUsage/industryType.do` | `year`,`month`,`apiKey` | `metroCd`,`cityCd`,`bizCd`,`returnType` |
| 산업분류별 전기사용고객 증감 | `change/custNum/industryType.do` | `year`,`month`,`metroCd`,`apiKey` | `cityCd`,`bizCd`,`returnType` |
| 공통코드 | `commonCode.do` | `codeTy`,`apiKey` | `returnType` |

메서드 GET/POST · 인코딩 UTF-8 · 응답 JSON/XML · 인증은 **query parameter `apiKey`**
(헤더 아님, 40자리). 상태코드 200/400/401/404/500/502. **pagination 없음.**
**호출 제한은 공표돼 있지 않다** — 포털 어느 화면에도 일일·분당 한도가 없다.

### 실호출로 확정한 것 (문서에 없던 것들)

1. **응답 필드명은 `powerUsage`** 다. 산업분류별 가이드 표의 `powerUseage` 는 오타다.
2. **지역코드 체계가 두 벌**이다. `commonCode.do?codeTy=metroCd` 는 한전 코드(경남 **38**),
   `codeTy=lglDngMetroCd` 는 법정동 코드(경남 **48**)를 준다.
   전력사용량 API 는 **법정동 코드**를 받는다(38 을 주면 404).
   창원 법정동 시군구코드: **120 창원시 / 121 의창 / 123 성산 / 125 마산합포 /
   127 마산회원 / 129 진해**. ROLE A 에서 "120/121 두 개"로 남겨둔 모호함은
   120 이 **통합 창원시**, 121 이 **의창구**로 확정됐다.
3. `businessType.do` 는 코드가 아니라 **이름**을 받고, `city=창원시` 로 주면
   **5개 구가 모두** 돌아온다(전방일치). 그래서 월 1회 호출로 창원 전체를 받는다.
4. `bizType` 값에는 **내부 공백이 여러 칸** 들어 있다("1차   금속", "섬      유").
   한 칸으로 줄여 조회하면 404 다.
5. `industryType.do` 의 `cityCd` 는 **2024년부터 404** 다(2023년까지는 120 이 동작).
   그래서 `metroCd=48` 만 주고 경남 전체를 받아 `city == '창원시'` 를 골라낸다.
6. **업종(bizType) 코드표는 공표되지 않는다.** `commonCode.do` 의 `codeTy` 는
   시도·시군구·계약종별·산업분류(KSIC 대분류)·발전원·복지할인까지만이고
   `bizTypeCd`/`bizType`/`busiCd` 는 모두 404 다.

## 4. KEPCO 업종 ↔ KICOX 크로스워크

`data/reference/industry_crosswalk/kepco_biztype_to_kicox.csv` (38행)

**`official_crosswalk = FALSE`.** 한전은 38업종의 정의도 코드표도 공표하지 않는다.
다만 근거 없는 키워드 매칭은 아니다. 업종명을 KSIC 중분류와 대조하면 제조업
구간(10~33)이 **명칭 단위로 거의 1:1** 이다 — 식료품제조=10, 섬 유=13, 1차 금속=24,
기타 기계=29, 자 동 차=30 … 예외는 세 가지뿐이다.

- KSIC 21(의약품)에 대응하는 업종이 **없다**
- KSIC 23 이 '유 리'·'시 멘 트' 둘로 **쪼개져** 있다
- KSIC 26 이 '영상. 음향'·'사무 기기' 둘로, KSIC 32+33 이 '가구및기타' 하나로

그래서 **KEPCO 업종명 → KSIC 중분류 → KICOX** 2단계로 잇고, 2단계째는 기존
`ksic_to_kicox.csv`(공표 분류 기준)를 그대로 쓴다. 등급은 원 분류체계에 공표
정의가 없으므로 **한 단계 내린다**(A→B, B→C, C→C). 분할·병합 업종은 부분포함이라 C.

| KICOX | KEPCO 업종 | 최저등급 |
|---|---|---|
| 음식료 | 식료품제조, 음료품제조 | **B** |
| 운송장비 | 자 동 차, 기타 운송 | **B** |
| 섬유의복 | 섬 유, 의복. 모피, 가죽. 신발 | C |
| 목재종이 | 목재. 나무, 펄프. 종이, 출판. 인쇄 | C |
| 석유화학 | 석유 정제, 화학 제품, 고무. 플라 | C |
| 비금속 | 유 리, 시 멘 트 | C |
| 철강 | 1차 금속 | C |
| 기계 | 기타 기계, 조립 금속 | C |
| 전기전자 | 전기 기기, 영상. 음향, 사무 기기, 의료. 광학 | C |
| 기타 | 가구및기타 | C |

등급 분포 B 12 / C 11 / D 15. **D 15개는 KICOX 에 배정하지 않았다** —
농림어업·광업(석탄. 원유, 금속비금속)·수도·재생재료와, 산업이 아니라 용도 구분인
가정용부문·순수써비스·사업자 용·관 공 용·국 군 용·유엔군 용·기타공공용·전 철이다.

> **이 38업종 목록은 순수한 산업분류가 아니다.** 제조업 세분류와 용도별 계약 구분이
> 섞여 있다. '업종 합계 = 창원 전력 총량' 으로 읽으면 안 된다.
> 또 '금속비금속' 은 이름과 달리 **광업** 항목이다(목록상 '석탄. 원유' 바로 뒤).

### 크로스워크 범위의 실증 확인

업종별 API 의 제조업 업종 합계 ÷ 산업분류별 API 의 KSIC C 제조업 = 중앙값 **0.9966** (범위 0.9939~0.9997), YoY 상관 **0.994** (n=13).

서로 다른 두 endpoint·분류체계가 총량에서 일치한다는 뜻이다. **제조업 '범위' 대응은 실증 확인됐고, KICOX 10업종 '배분'의 정확성은 여전히 확인되지 않았다.** 둘을 같은 근거로 쓰지 않는다.

## 8-2. 공간단위 — 「성산구 = 창원국가산단」이 얼마나 틀리는가

창원시 공장등록현황(공공데이터포털 3066436) 5,636건에서 법정동을 추출했다. 주소 해석 99.7%, 그중 KEPCO 법정동 목록과 일치 99.9%.

| 항목 | 값 |
|---|---|
| 창원 법정동 수 | 156 |
| 제조업 집적 법정동 (공장 30건 이상) | 18 |
| 집적 법정동의 창원 제조업 전력 비중 | **98.39%** |
| 성산구 전체의 창원 제조업 전력 비중 | **74.77%** |
| 성산구 안에서 집적 법정동 비중 | 98.46% |

**성산구를 창원국가산단 대용으로 쓰면 창원 제조업 전력의 25.2%가 시야에서 사라진다.** 의창구 팔용동·진해구 남양동·마산회원구 봉암동처럼 성산구 밖에 있는 집적 법정동이 그만큼을 차지한다. 반대로 성산구 안쪽은 집적 법정동이 98.5%로 거의 전부여서, 성산구를 쓰면 산단 밖 수요까지 함께 들어온다. 양방향으로 어긋난다.

집적 법정동 목록: 마산합포구 진동면, 마산합포구 진북면, 마산합포구 진전면, 마산회원구 내서읍, 마산회원구 봉암동, 마산회원구 양덕동, 성산구 남산동, 성산구 내동, 성산구 대원동, 성산구 성산동, 성산구 성주동, 성산구 신촌동, 성산구 웅남동, 의창구 대산면, 의창구 동읍, 의창구 북면, 의창구 팔용동, 진해구 남양동

## 9. 주장 강도 — 직접 입증 / 간접 시사 / 입증 불가

### 9-1. 직접 입증 (자료와 코드가 확인한 사실)

- 업종별 전력자료는 2022Q2~2026Q2 **17개 분기**만 `COMPLETE` 다. 2021년은 `NO_DATA` 다.
- 업종별 API 의 제조업 합계와 KSIC C 제조업 총량이 일치한다 (비율 중앙값 0.9966, YoY 상관 0.994).
- 업종 단위에서 생산·고용 YoY 와 전력 YoY 의 방향 일치율은 54.5% · 50.0% 이고, BH-FDR 보정 후 유의한 업종은 0개다.
- 2021년 대체자료는 실재하며 창원 법정동 206개 × KSIC 중분류로 제공되지만, 창원 행의 58.8% 가 비식별 처리돼 있다.
- 창원 제조업 전력의 98.4%가 공장 집적 법정동 18곳에 몰려 있고, 성산구 전체는 74.8%에 그친다.
- 403 은 인증상품 미등록·호출 한도·잘못된 키 때문이 **아니다**. 포털 인증키 현황에 API별 상품 등록 개념이 없고, 당일 호출집계에 4개 API 가 모두 정상 집계된다.
- Triage 결과는 이 분석 전후로 동일하다 (행 180 / {'관찰': 128, '추가확인': 35, '우선점검': 17}).

### 9-2. 간접적으로 시사 (가능한 설명 · 진단적 해석)

- 총전력·고객당 전력·계약전력 대비 사용량이 **함께** 내려가는 업종-분기는 가동 축소가 설비·계약 축소까지 진행됐을 **가능성**을 시사한다. 확정이 아니다.
- 월별 감소가 `PERSISTENT` 인 분기는 일시 충격보다 지속 요인일 **가능성**이 크다.
- 전력 신호와 생산·고용 신호가 **엇갈리는** 업종-분기는 오류가 아니라 현장 확인이 필요한 지점이다.

### 9-3. 입증 불가 (현재 자료로 말할 수 없는 것)

- **자가발전·에너지효율 개선·기업별 가동률** — 측정 자료가 없다. 전력 감소를 이 원인들로 설명하는 것도, 배제하는 것도 불가능하다.
- **창원국가산단 단위의 활동** — 공간단위가 행정구·법정동명이고 산단 경계 대응표가 없다.
- **전력 → 생산의 선행성** — 표본이 부족하고 lead/lag 는 탐색적 수준이다.
- **2021년 업종별 실적** — 같은 정의의 원자료가 공식적으로 존재하지 않는다.
- **고객 증감의 사업체 수 해석** — 단위가 KWH 이고 산식이 미공표다.

## 11. 최종 지위와 남은 한계

**`PARTIAL_CONTEXT`.** 근거는 다음 여섯 축이다.

| 기준 | 평가 |
|---|---|
| 시간 완전성 | 업종별 17개 분기만 `COMPLETE`. 2021년 결손은 공급측이라 복구 불가 |
| 분류 정합성 | 제조업 '범위'는 실증 확인. KICOX 10업종 '배분'은 미확인 (B~D) |
| 공간 정합성 | 행정구·법정동명까지. 산단 경계 대응 불가 |
| 변수 정의 | 전력·고객호수·계약전력은 명확. 고객증감은 미확정(`NOT_SUITABLE`) |
| 기존 생산·고용과의 관계 | 방향 일치·상관 모두 약함. 교차검증 역할은 못 한다 |
| 의사결정지원 활용 | 담당자 확인질문을 구체화하는 데는 실제로 쓸 수 있다 |

자료의 양이 많다는 이유로 `USABLE_CONTEXT` 로 올리지 않았다. 공간·분류 정합성이 맞지 않는 한 업종 판정을 지지하는 증거로 쓸 수 없기 때문이다. 반대로 `NOT_SUITABLE` 로 내리지도 않았다. 확인질문을 구체화하는 쓰임이 실재하고, 제조업 총량 계열은 전 구간 사용 가능하기 때문이다.

### 이번에도 해결하지 못한 것

1. 2021년 업종별 원자료 — 같은 정의의 공식자료가 존재하지 않는다.
2. 산단 경계 ↔ 법정동 정확한 overlay — 경계 polygon 과 법정동 코드가 없다. 집적 법정동은 상한이지 산단이 아니다.
3. `bizType` 공표 정의 — 없다. crosswalk 등급은 B~D 그대로다.
4. 고객증감 산식 — 미공표.
5. 에너지효율·자가발전 보정 — 자료 자체가 없다.
6. 일부 호출의 403 원인 — 인증상품 미등록·호출 한도·키 불일치 세 가설은 포털 화면으로 **기각**했으나, 무엇이 403 을 냈는지는 여전히 특정되지 않는다.
7. 2021 XLSX 의 ['06', '07', '08', '09', '11'] 월 — 파일이 잘렸고, 포털 시리즈가 2022년 4월부터라 **재다운로드로도 복구할 수 없다**. 판정에는 영향이 없다 — 12개월이 모두 있어도 정의 불일치로 `PARTIAL` 이다.
8. 2022~2026 법정동 × KSIC 자료를 실제로 수집·통합하는 일 — 경로는 확인됐으나 이번 범위 밖이다. 하더라도 36업종 계열을 대체하지는 못한다.
