# 강건성 보완 — 해석층·신뢰도층 도입

2026-09-18 · 창원국가산단 산업·고용 전환진단 모형

---

## 1. 무엇을 한 작업인가

모형을 하나 더 만든 것이 아니다. **같은 판정 위에 두 개의 층을 얹었다.**

```
KICOX 고용·생산
      ↓
   Triage            어느 업종을 어느 수준으로 확인할지 결정   ← 바뀌지 않음
      ↓
   해석층            무엇을 추가로 확인해야 하는지 설명       ← 신설
      ↓
   신뢰도층          다른 자료에서도 같은 방향인지,
                     자료의 한계가 무엇인지 표시              ← 신설
      ↓
   진단카드          판정 + 해석 + 신뢰도 + 질문 + 인계
```

새 자료는 **판정 입력이 아니다.** 세 가지 역할만 맡는다.

| 역할 | 자료 | 섞으면 안 되는 것 |
|---|---|---|
| 교차확인 (cross-check) | 고용보험 피보험자 — 같은 개념, 다른 출처·모집단 | 수준·점유율 비교, KICOX 값 대체 |
| 맥락 (context) | 수출 · 전력 · BSI — 다른 개념 | 업종 판정 입력, 업종별 배분 |
| 외부 준거 후보 | 고용유지지원금 등 행정 대응 이력 | 정답라벨, 정량 성능평가 |

## 2. Triage 는 무엇 하나 바뀌지 않았다

E/R/A/P 경계, A 기준, R 기준, 300인 게이트, Q3 반복조건, 생산 보강조건,
rolling backtest protocol/outcome, ELECTRE audit 결과 — 전부 그대로다.

`src/build_context_layer.py` 는 `decision_panel.csv` 를 읽기만 하며,
판정 열이 하나라도 달라지면 빌드가 중단된다. 작업 후 `src/run_triage_rule.py` 를
다시 실행해 `decision_panel.csv`, `decision_latest.csv`, `diagnostic_cards_latest.csv`,
`stage_distribution_by_quarter.csv` 가 **바이트 단위로 동일**함을 확인했다.

stage 분포: 관찰 128 · 추가확인 35 · 우선점검 17 (변동 없음).

## 3. 표현 감사

자세한 내용은 `docs/expression_audit.md`. 핵심만.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 업체 이탈형 / 가동 위축형 / 실질물량 감소형 | 업체수 감소 신호 / 가동 위축 신호 / 실질생산 위축 신호(PPI 조정) |
| 원인 유형 · 원인 판정 | 확인신호 프로필 (진단 프로필) |
| A~E 중 하나로 분류 | multi-label (동시 성립 허용) |
| 검증 자체가 필요 없다 | Triage 판정성능 재검증은 불필요. 해석층에는 QA·정의검증·민감도·매핑검토가 필요 |
| 관측수 180 → 540 | 분기 신호가 3개월 중 몇 개월에 걸쳐 지속되는지 확인 (분기말 단일시점 의존 완화) |
| 실질생산 감소 | PPI 조정 생산 감소 신호 / 가격효과를 일부 조정한 생산지표 감소 |
| 고용유지지원금 = 정답라벨 | 행정 대응 이력 기반 외부 준거 후보 |
| 고용보험으로 KICOX 를 검증 | KICOX 산단 고용과 창원시 고용보험 지표의 방향을 교차확인 |

`docs/01_planning/methodology/…EDA계획.md` 3곳(실질 생산액 / "때문인지" 2곳)을
실제로 고쳤다. `outputs/` · `logs/` 아래 해시가 고정된 감사기록은 고치지 않았다 —
사후에 문구를 바꾸면 감사기록이 아니게 된다.

## 4. 확인신호 프로필 — 왜 multi-label 인가

업체수·가동률·PPI 조정 생산은 한 분기에 동시에 나빠질 수 있다.
순서대로 하나만 배정하면 나머지를 버린다. 2026Q2 기계는 가동 위축과 실질생산 위축이
동시에, 비금속은 업체수 감소와 생산유지·고용감소가 동시에 성립한다.

```
firms_op_decline_signal                  = True / False / <NA>
operating_rate_decline_signal            = True / False / <NA>
ppi_adjusted_production_decline_signal   = True / False / <NA>
production_maintained_employment_decline = True / False / <NA>
```

`<NA>` 는 '신호 없음' 이 아니라 '판단 불가' 다. PPI 매핑 C·D 등급과 생산자료
미확인 행이 여기 들어간다. 0 이나 '정상' 으로 바꾸지 않는다.

카드 요약용 `representative_signal` 은 **표시순서**에 따른 요약일 뿐이고,
신호가 2개 이상이면 "대표 확인신호는 유일한 원인이 아니다" 문구가 함께 나간다.

### 경계와 민감도

경계는 전부 OWN(업체수 −3%, 가동률 −3%, PPI 조정 생산 −5%).
−2/−3/−5%, −3/−5/−7% 격자로 흔들어 본 결과 최대 변동폭은 180행 중 6.7%였다.

주목할 점 하나: 업체수 감소 신호를 −5% 로 좁히면 **뒤집히는 행이 전부 소규모
업종(기타)** 이다. 소규모 집계군에서 비율 경계가 특히 불안정하다는 뜻이고,
그래서 소규모 트랙은 비율이 아니라 절대 개수를 먼저 읽는다.

**경계를 재설정하지 않았다.** 목적은 좋은 값 찾기가 아니라 안정성 확인이다.

## 5. 자료별로 실제 확인한 것

### 5-1. 고용 교차확인

업종 단위로 비교 가능한 것은 **3개 업종 · 7개 분기(180행 중 21행)** 뿐이다.
창원상의 보고서에 실린 고용보험 업종은 기계·장비 / 전기장비 / 자동차·부품 셋이고,
KICOX 10업종과의 대응은 B(기계) · C(전기전자) · C(운송장비)다.

| 업종 | 비교 가능 | 방향 일치 | 방향 불일치 | 등급 |
|---|---:|---:|---:|---|
| 기계 | 7 | 4 | 3 | B |
| 운송장비 | 7 | 7 | 0 | C |
| 전기전자 | 7 | 6 | 1 | C |

나머지 7개 업종은 `비교자료 없음`. 총계 수준(산단 제조업 vs 창원시 제조업
피보험자)에서는 일치 80행 · 불일치 60행 · 비교 불가 40행이다.

두 자료의 모집단이 다르다는 사실을 모든 행에 문구로 함께 저장했다.

### 5-2. 월별 지속성

| 지표 | 계산 가능 분기 | 행 |
|---|---|---:|
| 고용 · 가동업체 · 가동률 | 2023Q4, 2024Q1 | 20/180 |
| 생산 | 2022Q1~2024Q1 | 90/180 |

공공데이터포털은 업종별 자료 중 **생산만** 월별 파일을 남겼고, 고용·가동업체·
가동률의 월값은 연간보정본 xlsx(2022M10~2024M03)에만 있다. 월 YoY 는 12개월 전
값이 필요하므로 고용은 2023M10 부터 계산된다. 그리고 **2024Q2 부터 KICOX 공표주기가
분기로 바뀌어 월별 자료 자체가 없다.**

결과적으로 `monthly_data_unavailable` 이 160행이다. 이 행들의 카드에는
"분기말 단일시점 값에만 의존한 판단" 이라는 확인질문이 자동으로 붙는다.
이것 자체가 이번 작업의 결과다 — 월별 보강은 원했던 만큼 되지 않는다.

계산된 구간에서 3/3개월 감소 8행, 2/3개월 감소 2행.
2023Q4 기계(우선점검, 고용 −6.77%)는 3개월 모두 감소했고,
2024Q1 기계(관찰, −0.64%)도 3개월 모두 감소했다 — 폭은 작지만 방향은 이어진다.

### 5-3. 명목 · PPI 조정 생산

매핑 등급: A 108행 · B 18행 · C 36행 · D 18행.
부호가 갈리는 행 11건, 5% 경계가 갈리는 행 5건.

가장 큰 사례는 2022Q1~Q3 철강이다. 명목으로는 +32.3% / +26.8% / +9.2% 인데
PPI 조정으로는 −2.8% / −2.6% / −1.2% 다. 철강 가격이 급등한 구간이므로
명목 증가를 물량 증가로 읽으면 안 된다. 반대로 2024Q1 철강은 명목 −8.79%
(5% 경계 통과)인데 조정값은 −1.98% 여서 경계를 넘지 않는다.

C 등급(석유화학·전기전자)은 상위 통합 PPI 항목이 없어 가중치 근거가 없다.
단일값을 만들지 않고 후보별 low/high 밴드로만 표시하며, 단정형 위축 신호를
생성하지 않는다(테스트 D로 강제).

**Triage 의 P 축은 명목 기준 그대로다.** 위 어느 행에서도 판정은 바뀌지 않았다.

### 5-4. 소규모 집계 트랙

300인 게이트를 유지한 채 표시만 나눴다.

- 소규모 집계 트랙(고용 <300인): 66행 / 4개 업종
- `small_base_warning`(고용 <300인 **또는** 가동업체 ≤20개사): 84행

음식료는 고용 635명이라 메인 트랙이지만 가동업체가 4개사여서 경고가 붙는다.
업체 하나가 빠지면 −25% 가 되는 집계군이다.

모든 표시에 절대 개수를 병기한다: `5개 → 4개 (−1개, −20.0%)`.
−20.0% 와 −1개는 같은 사실이고, 앞쪽만 쓰면 과장이 된다.

이건 소규모 업종 배제가 아니다. 비율 변동성이 큰 집계군을 **다른 방식으로 읽는** 것이다.

## 6. 신뢰도층 — 점수로 합치지 않는 이유

플래그를 하나의 '신뢰도 점수' 로 묶으면 가중치를 정해야 하고, 그 가중치의 근거가
다시 없다. 이 프로젝트가 ELECTRE 가중치에서 겪은 문제가 그대로 반복된다.
그래서 합산하지 않고 나열한다.

180행 중 True 인 행 수:

`source_revision_warning` 120 · `monthly_data_unavailable` 160 ·
`small_base_warning` 84 · `ppi_mapping_uncertain` 54 ·
`op_rate_definition_break` 40 · `industry_mapping_uncertain` 24 ·
`employment_cross_source_agreement` 17 · `nominal_real_sign_disagreement` 11 ·
`source_missing` 10 · `monthly_signal_3of3` 8 ·
`employment_cross_source_disagreement` 4 · `monthly_signal_2of3` 2

### 이번에 새로 드러난 자료 문제

**가동률 공표 정의가 2024Q2 를 기점으로 바뀐다.** 2024Q1 까지는 월별 단순평균
근사값, 2024Q2 부터는 분기 공식값이다. 두 계열은 저장소에서 서로 다른 열
(`op_rate_approx` / `op_rate_official`)로 관리되고 있었지만, **YoY 를 계산하면
2024Q2~2025Q1 의 4개 분기(40행)에서 당기와 전년동기의 산출방식이 달라진다.**

해석층은 이 값을 버리지 않는다. 대신 `op_rate_definition_break = True` 로
표시하고 "정의 차이를 확인할 필요가 있다" 질문을 자동으로 붙인다.
2025Q2 부터는 양쪽 모두 공식 분기값이다.

## 7. 진단카드 — 실제 예시 3개 (2026Q2)

### 예시 1. 기계 — 우선점검 · 메인 트랙

```
[판정]   우선점검 — 고용감소 6.3%(진입경계 5% 통과) ·
         산단 제조업 고용의 3.47% 감소(상위경계 2.0% 통과) → 보강: 생산 19.5% 감소
[현재상태] Q1 S4 / Q3 상태 지속 2분기 / 반복 고용진입신호 False
[확인신호 프로필]  가동 위축 신호 · 실질생산 위축 신호(PPI 조정)
         대표: 가동 위축 신호
         ※ 대표 확인신호는 표시순서에 따른 요약이며, 유일한 원인이 아니다.
[교차확인] 고용보험 방향: 비교자료 없음
         월별 지속성: 월별 원자료 미제공
         명목·PPI조정 생산 방향: 일치 (명목 −19.5% / 조정 −20.5%, 매핑 A)
         가동업체: 1,453개 → 1,458개 (+5개, +0.3%)  ← 업체수 감소 신호는 없다
[자료품질] 연간보정 개정본 사용 구간 · 월별 원자료 미제공 구간
[확인질문] 가동률 하락이 일시적 생산조정인지 수주·수요 감소에 따른 것인지 확인할 필요가 있다.
         명목생산 변화에 가격효과가 포함되어 있으므로 실제 물량이 줄었는지 추가로 확인할 필요가 있다.
         이 분기는 월별 원자료가 공표되지 않아 분기 내 지속 여부를 확인할 수 없다.
         연간보정 개정본을 사용한 구간이다. 이후 재개정 시 값이 달라질 수 있다.
[인계 검토] 산업동향 · 기업지원
         ※ 검토 대상 기능의 제안이며 특정 사업·예산의 선정이 아니다.
```

고용과 생산이 함께 줄었지만 **가동업체수는 오히려 늘었다.**
"업체 이탈" 로 설명하면 틀린다. 카드는 그 사실을 그대로 보여준다.

### 예시 2. 목재종이 — 우선점검 · 신호 1개

```
[판정]   우선점검 — 고용감소 10.1%(상위경계 10% 통과) · 산단평균 대비 6.4%p 열위
         → 보강: 생산 12.9% 감소 / 직전 분기에도 진입신호(지속)
[현재상태] Q1 S4 / Q3 상태 지속 2분기 / 반복 고용진입신호 True
[확인신호 프로필]  실질생산 위축 신호(PPI 조정)   ← 단일 신호. 대표 문구 없음
[교차확인] 명목 −12.9% / PPI 조정 −15.3% (매핑 A, 방향 일치)
         가동업체: 45개 → 44개 (−1개, −2.2%)  ← −3% 경계 미달로 신호 아님
[자료품질] 연간보정 개정본 사용 구간 · 월별 원자료 미제공 구간
[확인질문] 명목생산 변화에 가격효과가 포함되어 있으므로 실제 물량이 줄었는지 확인 필요
[인계 검토] 산업동향
```

업체수 −2.2% 는 경계(−3%)를 넘지 않아 신호가 아니다.
그래도 절대 개수(−1개)는 카드에 남는다 — 담당자가 직접 판단할 수 있게.

### 예시 3. 비금속 — 관찰 · 소규모 집계 트랙

```
[판정]   관찰 — 고용 축 진입신호 없음          ← Triage 판정은 '관찰' 그대로
[현재상태] Q1 S2 / Q3 상태 지속 3분기
[확인신호 프로필]  업체수 감소 신호 · 생산유지·고용감소 신호
         대표: 업체수 감소 신호
```

## 8. 남은 한계

1. **월별 지속성은 180행 중 20행에서만 계산된다.** 2024Q2 이후 KICOX 가 분기
   공표로 바뀌었기 때문이며, 앞으로도 회복되지 않는다. 최신 분기 카드에는
   월별 지속성 정보가 원리적으로 없다.
2. **업종 단위 고용 교차확인은 3개 업종 21행뿐이다.** KOSIS 인증키를 발급받아
   고용보험 취득·상실 flow 를 확보하면 넓힐 수 있다(수집 코드 작성 완료).
3. **PPI 조정 생산은 전국 물가지수를 쓴다.** 산단·업종 고유의 가격변동과
   제품구성 변화는 제거되지 않는다. 물리적 생산량이 아니다.
4. **외부수요(수출)·전력 신호는 확보하지 못했다.** 관세청 API 는 인증키와
   HS6 전수 대응표가, 한전 API 는 인증키와 별도 포털 가입이 필요하다.
5. **외부 준거 후보는 여전히 0건이다.** 고용유지지원금은 지역×업종×분기로
   공개되지 않는다. 따라서 이번에도 정량 성능평가는 하지 않았다.
6. **해석층 자체의 경계는 OWN 이다.** 민감도는 냈지만 최적성은 입증되지 않았고,
   입증할 근거자료도 없다.
7. **`source_revision_warning` 이 120행이다.** 연간보정 구간이 넓어 값이 사후에
   바뀔 수 있다. 이번 포털 최신본 대조에서는 개정이 발견되지 않았다(50건 중
   48건 완전 일치, 2건은 표기 자릿수 차이).
