## 1. 무엇이 바뀌었나

직전까지 KEPCO 는 "endpoint 를 알 수 없다"는 이유로 `PARTIAL` 에 멈춰 있었다.
이번에 **로그인한 브라우저로 포털 `OPEN API 소개` 화면을 직접 열어**
(데이터공개 > OPEN API > OPEN API 소개, `cmsmain.do?scode=S01&pcode=000493`)
공식 요청 URL·인자·응답 필드를 확보하고 실제로 호출했다. 로그인 우회는 하지 않았다.

이전 기록의 오판 하나를 바로잡는다. `powerUsage/industryType.do` 가 돌려준
`errCd=404` 를 "업무명이 틀렸다"로 읽었지만, 포털 상태코드표는 **404 = 요청자료를
찾을 수 없음**이다. 경로는 처음부터 맞았고 인자가 문제였다.

그런데 명세를 확보한 뒤에도 상태는 `PARTIAL` 로 남는다. 이유가 바뀌었을 뿐이다.
**이전: 명세를 몰라서. 지금: 1순위 자료의 원자료가 2021년 내내 비어 있어서.**

## 2. 확보한 공식 명세

| API | endpoint (`https://bigdata.kepco.co.kr/openapi/v1/…`) | 필수 인자 | 선택 인자 |
|---|---|---|---|
| 업종별 전력사용량 | `powerUsage/businessType.do` | `year`,`month`,`apiKey` | `metro`,`city`,`bizType`,`returnType` |
| 산업분류별 전력사용량 | `powerUsage/industryType.do` | `year`,`month`,`apiKey` | `metroCd`,`cityCd`,`bizCd`,`returnType` |
| 산업분류별 전기사용고객 증감 | `change/custNum/industryType.do` | `year`,`month`,`metroCd`,`apiKey` | `cityCd`,`bizCd`,`returnType` |
| 공통코드 | `commonCode.do` | `codeTy`,`apiKey` | `returnType` |

메서드 GET/POST · 인코딩 UTF-8 · 응답 JSON/XML · 인증은 **query parameter `apiKey`**
(헤더 아님, 40자리). 상태코드 200/400/401/404/500/502. **pagination 없음.**
**호출 제한은 공표돼 있지 않다** — 포털 어느 화면에도 일일·분당 한도가 없다.

### 실호출로 확정한 것 (문서에 없던 것들)

1. **응답 필드명은 `powerUsage`** 다. 산업분류별 가이드 표의 `powerUseage` 는 오타다.
2. **지역코드 체계가 두 벌**이다. `commonCode.do?codeTy=metroCd` 는 한전 코드(경남 **38**),
   `codeTy=lglDngMetroCd` 는 법정동 코드(경남 **48**)를 준다.
   전력사용량 API 는 **법정동 코드**를 받는다(38 을 주면 404).
   창원 법정동 시군구코드: **120 창원시 / 121 의창 / 123 성산 / 125 마산합포 /
   127 마산회원 / 129 진해**. ROLE A 에서 "120/121 두 개"로 남겨둔 모호함은
   120 이 **통합 창원시**, 121 이 **의창구**로 확정됐다.
3. `businessType.do` 는 코드가 아니라 **이름**을 받고, `city=창원시` 로 주면
   **5개 구가 모두** 돌아온다(전방일치). 그래서 월 1회 호출로 창원 전체를 받는다.
4. `bizType` 값에는 **내부 공백이 여러 칸** 들어 있다("1차   금속", "섬      유").
   한 칸으로 줄여 조회하면 404 다.
5. `industryType.do` 의 `cityCd` 는 **2024년부터 404** 다(2023년까지는 120 이 동작).
   그래서 `metroCd=48` 만 주고 경남 전체를 받아 `city == '창원시'` 를 골라낸다.
6. **업종(bizType) 코드표는 공표되지 않는다.** `commonCode.do` 의 `codeTy` 는
   시도·시군구·계약종별·산업분류(KSIC 대분류)·발전원·복지할인까지만이고
   `bizTypeCd`/`bizType`/`busiCd` 는 모두 404 다.

## 4. KEPCO 업종 ↔ KICOX 크로스워크

`data/reference/industry_crosswalk/kepco_biztype_to_kicox.csv` (38행)

**`official_crosswalk = FALSE`.** 한전은 38업종의 정의도 코드표도 공표하지 않는다.
다만 근거 없는 키워드 매칭은 아니다. 업종명을 KSIC 중분류와 대조하면 제조업
구간(10~33)이 **명칭 단위로 거의 1:1** 이다 — 식료품제조=10, 섬 유=13, 1차 금속=24,
기타 기계=29, 자 동 차=30 … 예외는 세 가지뿐이다.

- KSIC 21(의약품)에 대응하는 업종이 **없다**
- KSIC 23 이 '유 리'·'시 멘 트' 둘로 **쪼개져** 있다
- KSIC 26 이 '영상. 음향'·'사무 기기' 둘로, KSIC 32+33 이 '가구및기타' 하나로

그래서 **KEPCO 업종명 → KSIC 중분류 → KICOX** 2단계로 잇고, 2단계째는 기존
`ksic_to_kicox.csv`(공표 분류 기준)를 그대로 쓴다. 등급은 원 분류체계에 공표
정의가 없으므로 **한 단계 내린다**(A→B, B→C, C→C). 분할·병합 업종은 부분포함이라 C.

| KICOX | KEPCO 업종 | 최저등급 |
|---|---|---|
| 음식료 | 식료품제조, 음료품제조 | **B** |
| 운송장비 | 자 동 차, 기타 운송 | **B** |
| 섬유의복 | 섬 유, 의복. 모피, 가죽. 신발 | C |
| 목재종이 | 목재. 나무, 펄프. 종이, 출판. 인쇄 | C |
| 석유화학 | 석유 정제, 화학 제품, 고무. 플라 | C |
| 비금속 | 유 리, 시 멘 트 | C |
| 철강 | 1차 금속 | C |
| 기계 | 기타 기계, 조립 금속 | C |
| 전기전자 | 전기 기기, 영상. 음향, 사무 기기, 의료. 광학 | C |
| 기타 | 가구및기타 | C |

등급 분포 B 12 / C 11 / D 15. **D 15개는 KICOX 에 배정하지 않았다** —
농림어업·광업(석탄. 원유, 금속비금속)·수도·재생재료와, 산업이 아니라 용도 구분인
가정용부문·순수써비스·사업자 용·관 공 용·국 군 용·유엔군 용·기타공공용·전 철이다.

> **이 38업종 목록은 순수한 산업분류가 아니다.** 제조업 세분류와 용도별 계약 구분이
> 섞여 있다. '업종 합계 = 창원 전력 총량' 으로 읽으면 안 된다.
> 또 '금속비금속' 은 이름과 달리 **광업** 항목이다(목록상 '석탄. 원유' 바로 뒤).

### 크로스워크 범위는 실증으로 확인됐다

서로 다른 두 API 를 맞대봤다. 업종별 API 의 **제조업 업종 합계** vs
산업분류별 API 의 **KSIC C 제조업**(창원시):

| 지표 | 값 |
|---|---|
| 수준 비율 (mapped / KSIC C) | 중앙값 **0.9966** (0.9939 ~ 0.9997) |
| YoY 상관 (Pearson, n=13) | **0.9942** |
| YoY 평균 절대차 | **0.15 %p** |

두 계열이 사실상 같다. **KEPCO 제조업 업종들의 합 = KSIC C 제조업**이라는 것이
가정이 아니라 관측으로 확인됐다. 다만 이것은 **총량 수준의 확인**이며,
KICOX 10업종으로의 **배분 정확성은 보증하지 않는다.**

없으므로 **사용하지 않는다.** KICOX 입주업체수와 같은 개념이라고 가정하지도 않았다.

## 8. 무엇이 입증되고, 무엇이 아닌가

**직접 입증되는 것**
- 포털 OPEN API 의 공식 명세(endpoint·인자·응답·상태코드)와 실제 동작.
- 창원시 5개 구 × 36업종 × 월 전력사용량이 **2022-02~2026-06 구간에 존재**한다.
- 창원 제조업(KSIC C) 전력사용량은 **2021-01~2026-06 전 구간** 확보되며,
  2023Q4 이후 **YoY 가 지속적으로 마이너스**다(−4.9 % ~ −0.9 %, 2026Q2 만 +0.75 %).
- 업종별 API 의 제조업 합계 = 산업분류별 API 의 KSIC C 제조업 (YoY 상관 0.994).
  → crosswalk 의 **제조업 범위**가 실증 확인됐다.

**간접적으로 시사하는 것**
- 창원 제조업 전체의 조업강도가 2023Q4 이후 완만히 축소돼 왔을 가능성.

## 10. 결론과 남은 한계

**최종 상태 `PARTIAL`.**
명세·호출은 `VERIFIED` 이고 산업분류별 자료는 `USABLE` 이지만,
KICOX 업종 분석에 필요한 **1순위 자료(업종별)가 분석기간의 앞 5개 분기를 덮지 못한다.**
확보한 13분기에서도 업종 단위 교차검증 신호가 확인되지 않는다.

`NOT_SUITABLE` 로 내리지는 않았다. 분석단위(창원 구 × 업종 × 월)는 프로젝트와 맞고,
제조업 총량 계열은 전 구간 사용 가능하며, 크로스워크 범위가 실증 확인됐기 때문이다.

남은 한계
1. 업종별 2021-01~2022-01 원자료 결손 — 공급측 문제라 재수집으로 해결되지 않는다.
2. 공간단위가 행정구까지다. 산단 경계 자료는 제공되지 않는다.
3. 업종 분류체계에 공표 정의가 없다(`official_crosswalk = FALSE`).
4. 업종별 유효표본이 13분기 × 10업종뿐이다. 업종당 13개로는 상관·시차 추정이 약하다.
5. 호출 제한이 공표돼 있지 않다. 현재 규모(198회)에서는 429 를 만나지 않았을 뿐이다.
6. 고객 증감 자료는 단위가 불명이라 쓰지 않았다.
7. 전력집약도·자가발전 보정을 하지 않았다. 할 자료가 없다.
