## 1. 인증정보 취급

| 키 | 상태 |
|---|---|
| `KOSIS_API_KEY` | AVAILABLE |
| `DATA_GO_KR_SERVICE_KEY` | AVAILABLE |
| `KEPCO_API_KEY` | AVAILABLE |
| `ECOS_API_KEY` | AVAILABLE |

값은 어디에도 남기지 않았다. 확인한 것은 존재 여부뿐이다.

- `.env.txt` 는 **Git 추적 안 됨**, **과거 커밋 이력 없음**, `.gitignore:25 (.env.*)` 로 이미 차단.
  보강으로 `*_api_key.txt`, `*_apikey.txt` 를 추가했다.
- `src/evidence/collection/secrets.py` 를 새로 두어 `.env.txt` → `.env` 순으로 읽고,
  키를 다른 파일로 복사하지 않는다.
- `http_client.Response` 가 **생성 시점에** URL·오류문자열을 마스킹한다. 예외 메시지에
  요청 URL(=키 포함)이 끼어드는 경로를 막기 위해서다.
- 저장 직전 `secrets.assert_clean()` 으로 산출물에 키가 섞였는지 확인한다.
- 회귀검사 `tests/test_external_data.py::test_api_keys_never_appear_in_any_artifact`
  가 저장소 전체 텍스트 파일을 훑는다.

### 실측으로 드러난 키 취급 함정

공공데이터포털 인증키는 **Encoding 형태**였다. `urlencode` 로 다시 인코딩하면
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR(403)` 이 난다. 그대로 붙여야 200 이다.
"키가 잘못됐다" 가 아니라 "인코딩을 두 번 했다" 였다.

## 3. KOSIS — 고용 flow

### 받은 것

고용노동부 『사업체노동력조사(지역편)』 `행정구역(시군구)/산업별 고용`.
창원시(`ZONE2017A383811`) × `광업.제조업(BC)` × 반기로
**전체종사자 · 입직자 · 이직자 · 빈일자리**(+각 비율)를 확보했다.
2018상~2026상 17개 반기, 결측 반기 0.

### 받지 못한 것

**고용보험 DB 기반 시군구 × 산업중분류 × 월 피보험자/취득/상실 표는 KOSIS 에 없다.**

- 고용노동부(118) 통계표 17종을 확인했으나 해당 표가 없다.
- 경상남도 창원시(791)의 지역통계 4종
  (`DT_791007_2023A061` 산업별 피보험자수, `DT_791007_2023A062` 자격 취득·상실자수 등)은
  **통계표는 존재하지만 OpenAPI 조회 시 `err=30`(데이터 없음)** 을 반환한다.

따라서 "고용 순감소가 신규 유입 둔화 때문인가, 상실 증가 때문인가" 라는 질문에는
**창원시 제조업 전체 수준에서만** 답할 수 있고, 업종별로는 답할 수 없다.

### 업종 매핑

`labor_force_survey_to_kicox.csv` — 제조업이 한 덩어리라 **전부 등급 D**.
업종별 신호를 만들지 않는다. 모든 업종 카드에 '업종 공통 배경' 으로만 붙는다.

### 참고로 얻은 것

2026년 상반기 창원시 제조업: 종사자 +1.3%, 입직자 −1.1%, **이직자 +7.0%**.
입직과 이직이 반대 방향이라는 사실 자체가 카드의 확인질문이 된다.

### API 제약

`objL1='ALL'` 로 전국 시군구를 한 번에 받으면 `err=31`(40,000셀 초과).

마지막 반기가 잘린다 — 반기 코드(`202302`)로 줘야 한다.

## 4. 관세청 — 수출입 (HS6 모집단 기반으로 확대)

### HS6 목록을 추정하지 않고 원본에서 만들었다

`관세청_HS부호`(15049722)는 OpenAPI 로는 이 키에 미등록(403)이지만,
**파일데이터로는 인증키 없이 받을 수 있었다.** 상세페이지에 `contentUrl` 이 없는
'원문파일등록' 형식이라, 포털 JS(`script_fileDetail.js`)가 쓰는
`selectFileDataDownload.do` → `atchFileId` → `fileDownload.do` 경로를 따라 내려받았다.

| 원본 | 크기 | 쓰임 |
|---|---|---|
| `관세청_HS부호` (2026-01-01 적용본) | 1.4MB, HSK 10단위 12,469행 | 유효 HS6 추출(적용종료일자로 폐지 코드 제외) |
| `관세청_HSK별 신성질별·성질별 분류` | 2.6MB | 공표 `세번2단위품명`·`세번6단위품명` |

유효 HS6 **5,613개** 중 류 단위로 KICOX 업종 귀속 근거가 있는 **1,248개**를 모집단으로
확정했다(`hs6_universe_customs.csv`).

**매핑 근거로 쓴 것**: HS 류(2단위) + 관세청 공표 세번2단위품명.
**쓰지 않은 것**: 관세청 신성질별 분류(소비재/원자재/자본재) — **용도별** 분류이지
생산 업종 분류가 아니다. 참고 열로만 보존했다.

| 류 | KICOX | 등급 | HS6 수 |
|---|---|---|---:|
| 72·73 | 철강 | A | 291 |
| 87·89 | 운송장비 | A | 123 |
| 84 | 기계 | B (전산기기 8471 등 혼재) | 538 |
| 85 | 전기전자 | B | 296 |

**제외**: 비철(74~81), 광학·의료(90) 등 한 업종으로 귀속할 근거가 없는 류.

### 2단계 수집 (탐색 → 본수집)

1,248개 × 최근 1년으로 탐색 → 창원시 거래가 확인된 **1,029개**를 가려낸 뒤
나머지 연도창(2021~2026)으로 본수집했다. OpenAPI로 먼저 **34,258행**을 받았고,
아래 포털 일괄조회 보완 뒤 최종 **46,061행**, 2021.01~2026.06이다.

### 호출한도에 걸렸지만 공식 포털 일괄조회로 보완했다

6,393회 호출 중 **4,904번째부터 HTTP 429**가 반환됐다.
응답 본문은 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR / 일일 서비스 요청제한
횟수 초과 에러`. 포털 OpenAPI 의 **일일 호출한도**다.

| 구분 | HS6 수 |
|---|---:|
| OpenAPI만으로 6개 연도창 전부 확보 | 731 |
| 포털 CSV로 누락 연도창 보완 | 298 |
| 탐색에서 창원 거래 없음 | 219 |

연도창이 빠진 코드를 섞으면 그 해 합계가 과소집계되어 **YoY 가 왜곡된다.**
따라서 관세청 무역통계의 `지역별 실적` 화면에서 동일한 창원시 조건으로 61개 HS4와
`하위품목`을 선택해 연도별 CSV 6개를 받았다. OpenAPI라면 1,489회가 더 필요했던
결손을 **공식 화면 조회 6회**로 보완했고, 현재 미수집 조합은 **0개**다.

API와 포털의 중복구간에서 수출액·수입액·무역수지는 전부 일치했다. 신고 건수는
두 경로에서 달라 포털 보완행의 건수 필드는 공란으로 두고 원본 CSV에만 보존했다.
집계에는 여전히 **6개 창을 모두 확보한 코드만 사용**한다.

### 업종별 현재 상태

| 업종 | 집계 가능 HS6 | 미확보 HS6 | 2026Q2 수출 YoY | 상태 |
|---|---:|---:|---:|---|
| 기계 | 439 | 0 | −38.1% | usable |

각 업종의 전체 수출액으로 해석하지 않는다.

## 5. 한국전력 — PARTIAL 고정 (추측 호출 중단)

**인증키는 있다. 그러나 endpoint 명세가 로그인 뒤에만 공개된다** — 공식 문서로 확인했다.

data.go.kr 15101403 의 **참고문서**로 등록된 공식 『전력데이터개방포털 Open-API 사용 매뉴얼』
(pptx, 1.7MB)을 내려받아 전문을 확인했다. 4개 슬라이드 전부가 포털 화면 안내이고
**endpoint URL 과 파라미터를 싣지 않는다.**

> "전력데이터 개방포털 서비스는 **로그인 정보 기반으로 데이터 제공**함으로 회원가입 및 로그인 필수 진행"
> "OPEN API 소개 - OPEN API 의 **세부 내용(URL, 파라미터 등) 조회 가능 페이지**"

즉 URL·파라미터는 로그인한 회원에게만 공개된다. 로그인 우회는 하지 않는다.
포털 `robots.txt` 도 명명된 크롤러에 대해 `Disallow: /` 를 두고 있다.

앞서 시도한 경로(기록 보존, 재시도 금지):

| 시도 | 결과 |
|---|---|
| `bigdata.kepco.co.kr/openapi/v1/powerUsage/industryType.do` | JSON `errCd=404 NotFound` (라우터는 살아 있고 업무명이 틀림) |
| 같은 경로 `.json` / 확장자 없음 / 소문자 | HTML "잘못된 접근입니다" |
| data.go.kr 15101403 명세 | `"host":"apis.data.go.kr/B410002/"`, **`"paths":{}` 비어 있음** |
| `apis.data.go.kr/B410002/...` (포털 키) | `NO_OPENAPI_SERVICE_ERROR` |

**상태를 `PARTIAL` 로 고정하고 추가 추측 호출을 중단했다.**
매뉴얼 원본은 `data/raw/kepco/api/kepco_open_api_manual.pptx` 에 해시와 함께 보존했다.
포털에서 업무명을 확인해 `collect_kepco_power.py` 의 `OPERATION`/`PARAMS` 두 상수만 채우면
그대로 동작한다.

**`electricity_activity_panel.csv` 는 만들지 않았다.**
빈 패널이나 가짜 패널을 만들지 않는다는 원칙에 따른 것이다.

## 6. ECOS — 경기심리

### 지역 우선순위 적용 결과

창원 → 경남 → 전국 순으로 찾았다.

- **창원 단위 BSI 는 ECOS 에 없다.**
- **경남(`Z22`)은 있다** — `512Y019 지역별 기업경기조사(실적)`, 2013.01~, 월별.
  제조업 업황·생산·신규수주·가동률·인력사정 BSI 확보(340행).
- **업종 세분은 전국에서만 가능하다** — `512Y007 업종별 기업경기실사지수`,
  KSIC 중분류 18종(식료품·섬유·비금속·1차금속·기타기계장비·자동차·조선 등), 6,120행.

두 계열은 범위가 달라 섞지 않는다. 2021.01~2026.08, 95회 호출 전부 완전.

### 업종 매핑

`ecos_bsi_to_kicox.csv` — KICOX 9개 업종에 대응(기타 제외).
등급 A 13건 / B 3건 / C 1건. 다만 **전국 심리지수이므로 업종별 판정에 쓰지 않는다.**

### 정직한 평가 — BSI 의 변별력

- `bsi_region_below_100` 이 **180행 전부 True** 다. 경남 제조업 업황BSI 가 관측 전 기간
  기준선 아래였기 때문이다. **행 단위 변별력이 0 이다.**
- `bsi_industry_below_100` 도 161/180 True.

즉 BSI 는 "이 업종이 특별히 나쁜가" 를 가르지 못한다. 그래서 신호가 아니라
**배경**으로만 배치했고, 카드 문구도 "업종 고유 요인인지 지역 전반의 흐름인지
구분해 확인할 필요가 있다" 로 썼다. 변별력이 없다는 사실 자체가 그 확인질문의 근거다.

| 월별 지속성 | 20/180행 | 20/180행 **변화 없음** (KICOX 공표주기 문제라 외부키로 해소 불가) |
| 수출 | **미확보** | 창원시 × HS6 **1,029품목** × 66개월 **46,061행**. 4업종 모두 수집 결손 0 |
| HS6 기준자료 | 없음 | 관세청 원본 XLSX 2종 확보 → 유효 HS6 5,613개 / 모집단 1,248개 |
| 전력 | 미확보 | **PARTIAL 고정** — 공식 매뉴얼로 "endpoint 는 로그인 후 공개" 확인, 추측 중단 |
| 경기심리 | 전국 제조업 총계(sample 키, 340행) | 경남 지역 + 전국 업종별 **6,460행** |
| 외부 준거 후보 | 0건 | **0건 변화 없음** (고용유지지원금 KOSIS 재검색도 부재 확인) |
| 외부자료 인벤토리 | 15건 | 23건 (상태변경 8건) |

**정직하게 말하면**: 업종 단위 고용 교차확인은 **전혀 늘지 않았다**(21/180 그대로).
늘어난 것은 제조업 총계 수준의 flow 와, 4개 업종의 수출 맥락, 그리고 경기심리다.

## 9. 역할 분리

## 11. 남은 한계

1. **업종별 고용보험 flow 가 없다.** 확보한 flow 는 제조업 한 덩어리다(매핑등급 D).
2. **전력 미확보.** 가동률과 독립된 활동량 지표는 여전히 없다.
3. **수출은 여전히 업종 총액이 아니다.** 일일 호출한도 결손은 포털 CSV로 모두
   보완했지만, 귀속 근거가 있는 류만 담았다(비철·광학의료 등 제외).
   목재종이·비금속·음식료·섬유의복·석유화학·기타 6개 업종은 애초에 귀속 근거가
   있는 HS 류가 없다.
4. **BSI 는 행 단위 변별력이 없다.** 배경 이상으로 쓸 수 없다.
5. **외부 준거 후보는 여전히 0건.** 고용유지지원금은 인증키로도 해소되지 않았다.
6. **월별 지속성은 그대로 20/180.** KICOX 공표주기 문제라 외부 API 로 풀리지 않는다.
7. **고용 flow 는 반기 빈도이고 표본조사다.** RSE 를 함께 저장했다.
